Design and build a premium enterprise web application called “Kiro AI Consumption Governance”.

This is not a generic analytics dashboard.
This is not a one-page landing site.
This is not a static set of four dashboard tabs.

This product must feel like a full enterprise operating platform for AI consumption governance in Kiro.

The application should combine:
- executive governance visibility
- operational usage exploration
- cost-center and team accountability
- AI advisor and policy simulation
- evidence inspection
- strategic report generation
- analytics deep dives
- execution monitoring for advisor/report/simulation runs

The design should be inspired by premium dark enterprise operating systems such as the references shown:
- persistent dark shell
- refined top navigation
- contextual sub-navigation
- rich workspaces
- side-by-side analytics and simulators
- queue views
- detail views with tabs
- findings review surfaces
- execution traces and live console patterns
- premium charts embedded into the product rather than pasted onto a page

Core product promise:
Turn raw Kiro telemetry into a leadership-ready operating platform that answers:
1. What are we spending?
2. Who owns it?
3. What should we change?
4. What would happen if we apply new governance rules?
5. What evidence supports those decisions?

Hard truthfulness rules:
- Do not invent unsupported Kiro data.
- Do not present business outcome claims unless clearly marked as requiring external data.
- Do not show productivity ROI unless marked Productivity ROI*.
- Do not show budget variance unless marked Budget vs Actual*.
- Do not show realized savings unless marked Realized Savings*.
- Do not show infrastructure utilization, CPU, memory, or compute footprint.
- Do not imply true live telemetry unless a real streaming path exists.
- If the data source is export-driven, label it clearly as Daily Snapshot or Near Real-Time if justified.
- Keep the experience Kiro-native first, with external enrichments clearly marked using *.

Supported data families:
- Kiro subscription export
- Kiro daily user activity CSVs by client type
- group-to-user mapping
- box-to-cost-center mapping
- interaction telemetry
- flattened chat prompt logs
- flattened inline suggestion logs
- optional derived rollups, but only as helper layers

Business terminology:
- Box = Cost Center
- Group = Team
- User = Engineer
- Credits Used = AI Consumption
- Overage Credits = Overrun
- Workflow Area = Use Case
- Request Source = Interaction Channel
- Plugin_Name = Plugin
- MCP_Server = MCP Server
- Direct Kiro = direct Kiro interaction without plugin mediation
- No MCP Invoked = no MCP server used

Primary audiences:
- Executive sponsor
- Unit head
- Delivery manager
- Enterprise architect
- AI governance lead
- Engineering operations / FinOps lead

The product should feel like:
- an AI governance operating platform
- a premium enterprise command center
- a system leadership would use in a steering review
- a tool architects and delivery managers would use weekly

The app must use one consistent shell across all workspaces.

Global shell requirements:
- dark premium top navigation bar
- elegant product logo and name
- global search / command palette entry point
- top-right system status
- notifications
- user profile
- stable left or top workspace navigation
- optional contextual sub-navigation below the main shell when inside a workspace
- sticky filter bar when appropriate
- support for keyboard-friendly search and quick navigation

Search / command palette behavior:
Create a universal search / jump overlay that can search and navigate to:
- cost centers
- teams
- engineers
- request ids
- conversation ids
- models
- plugins
- MCP servers
- saved strategic reports
- advisor runs
- findings
- high-cost interactions
- governance policies
- simulation sessions

Do not make the product start with dense analysis.
The landing experience must begin simple and get deeper as users click.

Application information architecture:
Build the product as a platform with these main workspaces:

1. Governance Overview
2. Usage Explorer
3. Detail Workspace
4. Governance Findings
5. Policy & Simulation Studio
6. Execution Monitor
7. Analytics Deep Dive
8. Report & Evidence Console

These are not equal dashboard tabs with repetitive charts.
Each workspace has a distinct job in the user journey.

The ideal product journey is:
- user lands in Governance Overview
- sees current posture quickly
- searches or clicks into a Cost Center / Team / Engineer / Use Case
- enters a Detail Workspace
- reviews Findings
- runs AI Advisor or a policy simulation
- monitors execution
- inspects evidence
- generates and exports a strategic report

Visual design system:
Use a premium dark theme with strong contrast and subtle depth.

Primary palette:
- Background base: deep ink / midnight navy
- Surface 1: dark slate-blue
- Surface 2: slightly lighter analytics panels
- Border: low-contrast blue-gray hairlines
- Accent 1: electric blue
- Accent 2: indigo-violet
- Accent 3: teal / mint for healthy signals
- Warning: amber
- Risk / error: coral red
- Neutral labels: cool gray
- Text primary: off-white
- Text secondary: desaturated gray-blue

Gradients:
Use gradients carefully and intentionally.
Recommended:
- KPI accents: subtle blue-to-violet glows
- progress bars: electric blue to violet
- simulator CTA: bold blue-violet gradient
- selected state halos: soft blue outer glow
- chart area fills: transparent blue or violet fades, never overly saturated

Typography:
- large editorial, high-confidence page headings
- clean modern sans-serif for body, controls, and data labels
- strong title scale
- high legibility
- no tiny BI-tool typography
- labels and secondary metadata should feel quiet but readable

Spacing and composition:
- generous margins
- deliberate card spacing
- asymmetric but balanced grids
- large hero spaces on primary pages
- dense but clean tables
- use whitespace to separate meaning, not just decorate

Cards:
- rounded corners
- low-key border
- subtle shadow or glow
- differentiated card hierarchy
- avoid repeating identical plain panels everywhere

Motion:
- smooth but restrained
- state transitions when drilling in
- subtle hover and focus states
- loading shimmer for generated insights
- execution/simulation progress animation
- animated chart entrance only when useful

Do not use cheesy AI visuals.
Do not use excessive neon.
Do not use generic dashboard template aesthetics.

- clear click affordance

WORKSPACE 5: Policy & Simulation Studio

Purpose:
Interactive governance simulation and advisor workspace.
This is one of the most important workspaces.

It should combine:
- AI Advisor
- scenario modeling
- projected impact
- policy testing
- report generation initiation

This is not static text.
This must behave like a working studio.

Studio layout:
- left side: configuration and policy inputs
- center: current state + comparison
- right side: projected impact / advisor output / action summary

Allow users to configure:
- selected scope
- time range
- model routing policy
- plugin allowance or review policy
- MCP governance policy
- prompt-size threshold
- use case guardrails
- high-cost interaction threshold
- overrun alert threshold
- low-utilization seat threshold

Advisor modes:
- Executive Summary
- Cost Concentration Review
- License Hygiene Review
- Optimization Recommendations
- Model Routing Review
- Use Case Risk Review

Simulation types:
- Reduce oversized prompt context
- Route selected workflows to lighter models
- Flag plugin-heavy flows for review
- Limit MCP-heavy patterns
- Raise overrun alerts sooner
- Apply governance guardrails to selected use cases
- Compare current state vs proposed policy

Projected impact panel:
Show:
- projected AI consumption change
- projected overrun change
- affected users / teams
- likely policy friction areas
- highest impact use cases
- confidence or evidence note

Simulation CTA:
- Run Simulation
- Generate Advisor Summary
- Save Policy Scenario
- Generate Strategic Report
