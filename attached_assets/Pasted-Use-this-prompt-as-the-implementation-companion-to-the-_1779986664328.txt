Use this prompt as the implementation companion to the product vision prompt for “Kiro AI Consumption Governance”.

Goal:
Translate the product vision into an exact, buildable application spec for Replit.
Do not reinterpret the product as a generic dashboard.
Do not collapse it into four flat pages.
Follow this implementation spec closely.

Tech direction:
- Build as a modern web application, not a slideshow or landing page
- Use a consistent premium dark theme
- Favor React-style component thinking and reusable layout primitives
- Use a single persistent shell with workspace routing
- Use charting that supports:
  - line charts
  - stacked bars
  - grouped bars
  - scatter plots
  - heatmaps
  - treemaps
  - ranked horizontal bars
  - tables
- If mock data is used, wire every experience to the provided Kiro-style dataset semantics

Core app model:
The application has:
- one global shell
- one global search / command palette
- one shared filter model
- eight workspaces
- one consistent evidence drawer
- one shared strategic report generation flow
- one shared AI advisor simulation flow

JOIN RULES

Required joins:
- user activity to group mapping:
  - `UserId`
- interaction telemetry to group mapping:
  - `UserId`
- interaction telemetry to chat prompt logs:
  - `Request_Id`
  - fallback `Conversation_Id` if necessary
- interaction telemetry to inline prompt logs:
  - `Request_Id`
- subscriptions to user activity or group mapping:
  - use matching user identity field from available columns

Data integrity rules:
- do not render raw placeholder `none`
- use `Direct Kiro` for interactions without plugin mediation
- use `No MCP Invoked` for interactions without MCP usage
- exclude `Direct Kiro` from ranked plugin impact charts
- exclude `No MCP Invoked` from ranked MCP impact charts
- but allow both to appear in metadata and detail views

RESPONSIVE RULES

Desktop:
- full multi-column layouts
- right rails and split panes visible

Tablet:
- collapse some 3-column layouts into stacked 2-column
- execution and studio right panel may move below center panel

Mobile:
- preserve shell
- navigation collapses
- tables become horizontally scrollable or card lists
- evidence drawer becomes full-screen modal
- analytics deep dive should prioritize key charts and collapse others into sections

DO NOTS

- do not build flat static pages with all charts visible at once
- do not make every workspace look identical
- do not use pie charts where ranked bars or treemaps are more appropriate
- do not expose raw placeholder values like `none`
- do not make the AI Advisor a static text panel
- do not pre-render strategic reports without user action
- do not imply unsupported Kiro data
- do not use bland white dashboard cards on a dark shell
- do not let the app feel like a template demo

SUCCESS CRITERIA

The built application is correct if:
- Overview gives an executive posture in under one minute
- Explorer supports quick drill into cost center/team/engineer/interaction
- Detail Workspace feels like a true investigation page with tabs
- Findings feels like a governance review queue
- Studio supports interactive advisor and simulation workflows
- Execution shows realistic progress and status
- Analytics includes the full required chart inventory
- Reports/Evidence supports strategic report generation and evidence review
- all surfaced high-cost interactions open meaningful evidence
- the design feels premium, modern, dark, and deliberate
